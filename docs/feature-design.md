# 拓展功能设计文档：本地全文索引搜索

## 1. 功能概述

在 Ghost 原生不提供前台全文搜索的情况下，通过自定义主题实现**客户端本地全文索引搜索**，支持关键词高亮和无结果智能建议。

---

|------|----------|--------|

## 3. 数据来源

### 数据获取方式

通过 **Ghost Content API** 获取公开文章数据，构建客户端内存索引：

```
GET /ghost/api/content/posts/?key={content_api_key}&include=tags&limit=all&formats=plaintext
```

### 索引字段

| 字段 | 来源 | 权重 | 说明 |
|------|------|------|------|
| 标题 | `post.title` | 10 | 完整短语匹配额外 +50 |
| 标签 | `post.tags[].name` | 5 | 文章关联的标签名 |
| 正文 | `post.plaintext` | 1 | 纯文本内容（去除 HTML） |
| 摘要 | `post.excerpt` | 1 | 文章摘要 |

### 分词策略

- **英文**：按空格和标点分割为单词，转小写
- **中文**：采用 2-gram 滑动窗口分词（如"开源软件"→"开源""源软""软件"）
- **数字**：保留完整数字串

### 数据缓存

- 首次打开搜索时拉取数据，缓存到浏览器内存
- 页面刷新后重新拉取（不使用 localStorage，避免内容更新后搜索结果过时）
- 文章数量较少时（< 100篇），单次请求体积可控（约几十 KB）

## 4. 界面入口

### 入口位置

1. **导航栏搜索图标**：主题顶部导航栏右侧，放大镜图标
2. **快捷键**：`Ctrl+K`（Windows/Linux）或 `Cmd+K`（macOS）
3. **关闭方式**：点击遮罩层、点击关闭按钮、按 `ESC` 键

- 结果按匹配分数降序排列

## 5. 失败状态处理

| 失败场景 | 处理方式 | 用户感知 |
|----------|----------|----------|
| Content API 请求失败（网络错误） | 显示"搜索暂时不可用，请刷新页面重试" | 友好提示，不崩溃 |
| Content API 返回空数据 | 显示"暂无文章" | 空状态提示 |
| 搜索无匹配结果 | 显示热门标签 + 推荐文章（取最新5篇） | 引导用户浏览其他内容 |
| 关键词过短（单字） | 提示"请输入至少2个字符" | 避免无意义的宽泛匹配 |
| 浏览器不支持 fetch API | 降级为隐藏搜索入口 | 兼容老旧浏览器 |
| 文章内容过大导致内存占用高 | 限制索引字段（只索引标题+标签+前2000字正文） | 性能可控 |

### 错误处理代码逻辑

```javascript
try {
    const response = await fetch(apiUrl);
    if (!response.ok) throw new Error('API error');
    const data = await response.json();
    buildIndex(data.posts);
} catch (error) {
    showError('搜索暂时不可用，请刷新页面重试');
    console.error('Search index build failed:', error);
}
```

## 6. 隐私影响

### 数据处理原则

| 维度 | 说明 |
|------|------|
| **数据存储位置** | 仅在浏览器内存中，不写入 localStorage / IndexedDB / Cookie |
| **数据发送** | 仅在首次打开搜索时向同源 Ghost Content API 发送请求，不向第三方服务发送任何数据 |
| **搜索历史** | 不记录、不上传用户的搜索关键词 |
| **用户身份** | Content API 使用公开 key，不需要用户登录，不收集用户身份信息 |
| **数据留存** | 关闭页面或刷新后，内存索引自动清除，无持久化残留 |
| **Cookie** | 不设置任何额外 Cookie |
| **第三方依赖** | 搜索功能纯原生 JavaScript 实现，无第三方分析/追踪脚本 |

### 与 Ghost 原生搜索方案对比

| 方案 | 隐私影响 |
|------|----------|
| 本方案（本地索引） | 数据不出浏览器，无搜索历史记录 |
| Ghost 官方搜索（Algolia） | 文章数据同步到第三方 Algolia 服务器，存在数据出境风险 |
| 自建 Elasticsearch | 需要额外服务器，运维成本高，数据存储在自有服务器 |

## 8. 为什么放在主题层，而不是修改 Ghost 核心？

### 决策对比

| 维度 | 修改 Ghost 核心 | 放在自定义主题（本方案） |
|------|----------------|------------------------|
| **升级兼容性** | Ghost 升级时核心修改会被覆盖，需要重新合并冲突 | 主题独立于核心，Ghost 升级后主题仍可正常使用 |
| **维护成本** | 需要理解 Ghost 核心代码（Express + Bookshelf + Ember），学习成本高 | 只需要理解主题模板（Handlebars + JS），门槛低 |
| **部署复杂度** | 需要 fork Ghost 仓库，自行维护分支，无法使用官方更新 | 直接上传主题 zip 即可，零部署成本 |
| **可移植性** | 绑定特定 Ghost 版本，换博客系统无法复用 | 搜索逻辑可迁移到其他支持 Content API 的主题 |
| **风险隔离** | 核心代码出错可能导致整个博客无法运行 | 主题出错最多影响前台显示，管理后台不受影响 |
| **实验要求** | 违反"不修改 Ghost 核心代码"的约束 | 符合实验要求的二次开发边界 |

### 为什么不使用伴随服务（Sidecar Service）？

| 维度 | 伴随服务（如 Node.js 搜索服务） | 主题层本地索引（本方案） |
|------|-------------------------------|------------------------|
| **运维成本** | 需要额外进程、端口、进程管理（PM2/systemd） | 零额外运维，纯前端 |
| **资源消耗** | 需要常驻内存，维护搜索索引 | 按需加载，页面关闭即释放 |
| **部署复杂度** | 需要同时部署 Ghost + 搜索服务 | 只需要部署 Ghost |
| **适用场景** | 文章量大（>1000篇）、需要复杂搜索语法 | 个人博客（<100篇）、简单关键词搜索 |

### 结论

对于个人博客场景（文章量少、运维能力有限、需要快速迭代），**主题层本地索引**是最优选择：
- 符合实验"不修改核心"的约束
- 零额外运维成本
- 升级友好
- 隐私友好（数据不出浏览器）

### 文件级差异

| 文件 | 操作 | 说明 |
|------|------|------|

| `default.hbs` | 修改 | 集成搜索弹窗组件、引入 search.js、添加内联样式 |

| `partials/search-modal.hbs` | **新增** | 搜索弹窗组件模板 |
| `assets/js/search.js` | **新增** | 本地全文搜索引擎核心代码（约300行） |
| `assets/css/screen.css` | 未修改 | 复用 Source 主题原有样式 |

### 功能级差异

| 功能 | 上游基线（Source 主题） | 改造后（oss-blog-theme） |
|------|------------------------|------------------------|
| 前台搜索 | ❌ 无搜索入口 | ✅ 导航栏搜索图标 + Ctrl+K 快捷键 |
| 搜索方式 | 无 | 客户端本地全文索引（Content API + 内存） |
| 关键词高亮 | 无 | ✅ `<mark>` 标签黄色高亮 |
| 无结果处理 | 无 | ✅ 热门标签 + 推荐文章建议 |
| 文章卡片 | 标题+摘要+日期 | 标题+摘要+日期+**阅读时长** |
| 中文搜索支持 | 无 | ✅ 2-gram 中文分词 |
| 第三方依赖 | 无 | 无（纯原生 JS） |

### search.js 核心实现差异

上游 Source 主题无任何搜索相关 JS。本方案新增的 `search.js` 包含：

1. **索引构建器**（`buildIndex`）：拉取文章 → 分词 → 构建倒排索引
2. **分词器**（`tokenize`）：英文单词 + 中文 2-gram 混合分词
3. **搜索引擎**（`performSearch`）：加权评分 + 匹配阈值过滤
4. **高亮渲染器**（`highlightText`）：关键词 `<mark>` 包裹
5. **无结果建议器**（`showNoResults`）：热门标签 + 最新文章推荐
6. **UI 控制器**：弹窗打开/关闭、输入防抖、键盘事件
